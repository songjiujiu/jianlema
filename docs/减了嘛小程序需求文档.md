# 减了嘛小程序需求文档

版本：v0.1  
状态：草案  
产品定位：拍照打卡 + 体重管理 + 毒舌激励的减脂自律小程序

## 1. 项目背景

减肥用户常见问题不是不知道怎么减，而是缺少持续反馈、缺少仪式感、容易中断。一旦连续几天不记录，用户会迅速失去控制感。

「减了嘛」希望用轻量拍照打卡、连续记录、进度对比和有记忆点的毒舌激励，帮助用户每天面对自己的身体变化和行为结果。

核心不是羞辱用户，而是用用户主动选择的“犀利提醒”制造情绪冲击，让用户重新行动。

## 2. 产品目标

1. 让用户每天完成一次减脂打卡。
2. 让用户可以直观看到身体变化、体重变化和连续打卡状态。
3. 当用户中断打卡时，通过弹窗提醒形成强刺激召回。
4. 用差异化文案建立产品记忆点，形成传播话题。
5. MVP 阶段尽量轻量，优先验证用户是否愿意持续打卡。

## 3. 目标用户

### 3.1 核心用户

- 正在减脂、塑形、控体重的人。
- 想用照片记录身材变化的人。
- 需要外部刺激、监督和反馈的人。
- 喜欢“毒舌”“嘴硬但有效”风格的人。

### 3.2 排除或谨慎覆盖用户

- 未成年人。
- 有进食障碍、严重身材焦虑或心理健康风险的用户。
- 不接受强刺激文案的人。

产品应提供温和模式和关闭毒舌提醒的入口，避免把单一风格强加给所有用户。

## 4. 核心卖点

- 每天一张照片，真实记录变化。
- 未打卡自动弹窗，提醒用户别逃避。
- 毒舌但有边界的激励文案，形成产品个性。
- 身材进度相册，支持前后对比。
- 连续打卡天数、体重趋势、阶段目标可视化。

## 5. MVP 范围

### 5.1 必须做

- 微信登录。
- 用户基础资料设置。
- 每日拍照打卡。
- 可选体重记录。
- 今日是否打卡状态判断。
- 下次打开小程序时，如果上一自然日或当天应打卡但未打卡，弹窗提醒。
- 打卡日历。
- 进度照片列表。
- 毒舌提醒文案池。
- 温和提醒模式。
- 基础隐私说明和图片删除能力。

### 5.2 暂不做

- AI 身材评分。
- AI 饮食识别。
- 社区广场。
- 付费会员。
- 私教课程。
- 好友 PK。
- 智能训练计划。

这些能力可以在 MVP 验证后再做，避免第一版过重。

## 6. 用户流程

### 6.1 首次进入

1. 用户打开小程序。
2. 授权微信登录。
3. 阅读隐私说明。
4. 设置昵称、性别可选、身高可选、当前体重可选、目标体重可选。
5. 选择提醒风格：
   - 温和模式。
   - 犀利模式。
   - 地狱模式，需二次确认。
6. 进入首页。

### 6.2 每日打卡

1. 用户进入首页。
2. 点击“今日打卡”。
3. 选择拍照或从相册上传。
4. 可填写今日体重、备注、心情。
5. 提交成功。
6. 首页展示今日已打卡、连续打卡天数、最近体重变化。

### 6.3 未打卡召回

1. 用户某天没有完成打卡。
2. 下次打开小程序时，系统判断是否存在漏打卡。
3. 弹出提醒弹窗。
4. 用户可以选择：
   - 现在补打卡。
   - 今天重新开始。
   - 先放过我一次。
5. 关闭后进入首页，但首页仍展示漏打卡状态。

### 6.4 查看进度

1. 用户进入“进度”页面。
2. 查看日历打卡状态。
3. 查看照片列表。
4. 选择两张照片进行前后对比。
5. 查看体重趋势。

## 7. 功能需求

## 7.1 首页

### 功能描述

首页是用户每天打开后的核心操作页，必须快速告诉用户今天是否完成打卡。

### 页面元素

- 今日日期。
- 今日打卡状态。
- “拍照打卡”主按钮。
- 连续打卡天数。
- 当前体重和目标体重。
- 最近 7 天打卡概览。
- 今日激励文案。

### 规则

- 当天已打卡：主按钮显示“查看今日记录”或“再次打卡”。
- 当天未打卡：主按钮显示“今日打卡”。
- 如果有漏打卡：顶部展示轻提示或弹窗提醒。

## 7.2 拍照打卡

### 功能描述

用户每天通过照片记录身体状态，可附加体重和备注。

### 字段

- 打卡日期。
- 照片。
- 体重，可选。
- 备注，可选。
- 心情，可选。
- 创建时间。

### 规则

- 每天至少允许 1 次打卡。
- 是否允许多次打卡可配置，MVP 建议允许多次，但首页默认展示最后一次。
- 上传照片前提示用户注意隐私。
- 用户可以删除自己的打卡记录。

## 7.3 未打卡弹窗

### 功能描述

如果用户当天没有打卡，下次打开小程序时弹窗提示。考虑实际体验，建议判断“上一次应该打卡但未打卡”的情况，而不是用户早上刚打开就骂。

### 触发条件

MVP 建议采用以下规则：

- 用户不是首次进入。
- 用户已设置提醒风格。
- 当前时间超过用户设定的每日打卡截止时间。
- 当天没有打卡，或上一个自然日没有打卡。
- 同一漏打卡事件只弹一次，避免反复打扰。

### 弹窗内容

- 标题。
- 毒舌提醒文案。
- 漏打卡天数。
- 主按钮：现在打卡。
- 次按钮：先放过我。

### 文案边界

可以犀利，但不建议直接使用“废物”作为默认文案。原因：

- 容易触发平台审核风险。
- 容易造成用户反感或心理压力。
- 会把攻击点落在人格和身材上，而不是行为上。

建议做成用户主动开启的“地狱模式”，并提供明确开关。

### 文案示例

温和模式：

- 今天还没打卡，别让昨天的努力白费。
- 记录一下吧，改变都是从面对开始的。
- 不用完美，但别消失。

犀利模式：

- 又想假装没这回事？体重秤可不会陪你演。
- 今天没打卡，懒惰已经替你签到了。
- 你可以骗小程序，但骗不了裤腰。
- 别躲了，拍一张，看看今天有没有认真活成目标版自己。

地狱模式：

- 连一张照片都不敢拍，怎么指望身材听你的？
- 今天又输给嘴和懒了？现在打卡还来得及。
- 你不是没时间，你是在给放弃找台阶。
- 别把目标挂嘴上，把今天的打卡交出来。

## 7.4 进度相册

### 功能描述

展示用户历史打卡照片，帮助用户看到变化。

### 能力

- 按时间倒序展示照片。
- 支持按月份筛选。
- 支持查看某一天详情。
- 支持删除照片。
- 支持选择两张照片对比。

## 7.5 打卡日历

### 功能描述

通过日历展示用户打卡连续性。

### 状态

- 已打卡。
- 未打卡。
- 今日未完成。
- 补打卡。

### 规则

- 补打卡需要标识，避免和真实当天打卡混淆。
- 连续天数是否包含补打卡，需要产品配置。MVP 建议不计入连续天数。

## 7.6 体重记录

### 功能描述

用户可以在打卡时同步记录体重，也可以单独更新体重。

### 能力

- 当前体重。
- 目标体重。
- 体重趋势图。
- 较上次变化。
- 距目标差值。

### 注意

不应强制用户每天填体重，避免制造过度焦虑。照片打卡是主流程，体重是辅助信息。

## 7.7 提醒设置

### 功能描述

用户可以设置每天提醒打卡时间和文案强度。

### 字段

- 每日提醒时间。
- 打卡截止时间。
- 文案模式。
- 是否开启漏打卡弹窗。
- 是否允许订阅消息提醒。

### 规则

- 订阅消息需要用户主动授权。
- 弹窗只在小程序内出现。
- 用户随时可以关闭犀利提醒。

## 9. 状态判断逻辑

### 9.1 今日打卡状态

输入：

- 当前用户 ID。
- 当前日期。
- 用户所在时区。

输出：

- hasCheckedInToday。
- latestCheckin。
- streakDays。

逻辑：

1. 查询当前日期是否存在打卡记录。
2. 如果存在，返回已打卡。
3. 如果不存在，返回未打卡。
4. 根据历史连续日期计算连续打卡天数。

### 9.2 漏打卡弹窗状态

输入：

- 当前日期。
- 当前时间。
- 用户打卡截止时间。
- 最近一次打卡日期。
- 弹窗展示记录。

输出：

- shouldShowMissedPopup。
- missedDate。
- copywriting。

逻辑：

1. 首次用户不弹。
2. 如果当天未超过截止时间，不弹当天漏打卡。
3. 如果上一个自然日未打卡，并且该漏打卡日期没有展示过弹窗，则弹。
4. 如果当天超过截止时间且未打卡，可以弹当天提醒。
5. 同一天最多弹一次。

## 11. 非功能需求

### 11.1 隐私

- 照片属于敏感个人数据，默认仅本人可见。
- 上传前明确提示用途。
- 支持用户删除照片和打卡记录。
- 不做公开展示，除非用户主动分享。
- 上线前按微信小程序现行隐私保护和平台审核要求补齐隐私声明。

### 11.2 安全

- 图片访问需要权限控制。
- 服务端校验用户只能访问自己的记录。
- 防止通过参数枚举访问他人图片。
- 敏感接口需要登录态。

### 11.3 性能

- 首页首屏 2 秒内可用。
- 图片上传需要压缩。
- 进度相册分页加载。
- 趋势图按需加载。

### 11.4 可用性

- 打卡入口必须明显。
- 不强迫用户填写过多资料。
- 弹窗必须可以关闭。
- 毒舌模式必须可以调整或关闭。

## 13. 风险与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 文案过度攻击 | 可能引起用户反感或审核风险 | 默认温和，犀利和地狱模式需用户主动开启 |
| 隐私风险 | 用户上传身材照片 | 默认私密、可删除、权限隔离 |
| 减肥焦虑 | 过度强调体重可能造成压力 | 体重可选，照片记录为主 |
| 打卡疲劳 | 用户几天后失去兴趣 | 连续天数、进度对比、文案变化 |
| 功能过重 | 第一版做太多导致延期 | MVP 只做打卡、弹窗、进度 |

## 15. 验收标准

1. 新用户能在 1 分钟内完成首次打卡。
2. 用户当天打卡后，首页状态正确展示已打卡。
3. 用户未打卡时，下次打开能按规则出现提醒弹窗。
4. 同一漏打卡事件不会无限重复弹窗。
5. 用户能查看历史打卡照片。
6. 用户能删除自己的照片和记录。
7. 用户能切换提醒文案强度。
8. 用户关闭毒舌模式后，不再出现犀利文案。

## 16. 待确认问题

1. 是否允许补打卡。
2. 连续打卡是否包含补打卡。
3. 每天是否允许多张照片。
4. 照片是否存微信云开发，还是自建对象存储。
5. 是否需要体重趋势图进入 MVP。
6. 是否做分享海报。
7. 地狱模式文案是否需要后台动态配置。
8. 是否需要管理员后台审核和更新文案。

## 17. MVP 推荐结论

第一版只围绕一个核心闭环：

用户打开小程序 -> 看到今天没打卡 -> 拍照打卡 -> 看到连续记录 -> 第二天再回来。

「减了嘛」最有差异化的是未打卡后的情绪刺激，但这把刀要拿稳。建议默认用“犀利但不羞辱人格”的文案，把更狠的话放进用户主动开启的地狱模式里，并且随时允许关闭。
